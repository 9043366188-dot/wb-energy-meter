## [0.9.0] — 2026-09-08

### Добавлено

- **Самообновление из GitHub по кнопке.** В «Настройках» новый блок
  «Обновление»: показывает текущую версию, по кнопке «Проверить
  обновления» сверяется с веткой `main` на GitHub, при наличии новой
  версии — кнопка «Обновить сейчас» с диалогом подтверждения. Источник
  — только ветка `main`, не теги: что в `main`, то и приезжает на
  контроллер. Автопроверки нет — сервис не ходит в интернет, пока
  пользователь не нажал кнопку.
- **Автоматический откат.** Если после установки сервис не отвечает на
  `/health` в течение 90 секунд (`systemctl is-active` + HTTP-проверка,
  опрос раз в 3 с) — автоматический откат на предыдущую версию из
  резервной копии `/opt/wb-energy-meter.rollback`. Если откат тоже не
  помог — статус `failed` с прямой инструкцией зайти по SSH.
- `scripts/self-update.sh` — новый скрипт: захват блокировки (`flock`),
  скачивание tarball ветки `main`, проверка целостности архива (5
  обязательных файлов) и `python3 -m compileall` **до** подмены
  рабочего кода, резервное копирование, установка через `install.sh`,
  проверка после установки, откат при неудаче. При любом падении в файл
  статуса гарантированно пишется терминальное состояние (`trap ERR` +
  `trap EXIT`) — UI не может залипнуть в «идёт обновление» навсегда.
  Логи — `/var/log/wb-energy-meter/update.log` (ротация: 5 файлов или
  1 МБ).
- **Апдейтер запускается через `systemd-run --collect`**, а не как
  дочерний процесс сервиса — иначе `systemctl stop` из `install.sh`
  убил бы апдейтер вместе с сервисом посреди обновления (см. AGENTS.md,
  раздел про cgroup/`KillMode`). Фолбэк на `setsid nohup`, если
  `systemd-run` недоступен.
- `wb_energy_meter/updater.py` — новый модуль, только стандартная
  библиотека (`urllib.request`, `json`, `subprocess`): проверка версии
  на GitHub (`check_remote`), сравнение с установленной
  (`is_update_available`), атомарное чтение/запись статуса
  (`read_status`/`write_status`), запуск апдейтера (`start_update`).
- API: `GET /api/update/check`, `GET /api/update/status`,
  `POST /api/update/start`. `start` защищён от установки не той версии,
  что видел пользователь: тело `{"commit": "<sha>"}` сверяется с
  актуальным sha на GitHub на момент запуска, при расхождении — 409.
  Повторный запуск во время уже идущего обновления — 409.
- Новая секция конфига `update:` (`enabled`, `allow_from_ui`,
  `repo_owner`, `repo_name`, `ref`, `check_timeout_s`). Старые конфиги
  без этой секции продолжают работать — значения по умолчанию в коде.
- `install.sh` теперь копирует `scripts/` целиком в
  `/opt/wb-energy-meter/scripts/` (нужно, чтобы `self-update.sh` был
  доступен из установленного дерева, а не только из временного архива)
  и пишет `/opt/wb-energy-meter/VERSION.json` (версия, commit, ref,
  время установки). Поддержан `SKIP_APT=1` для самообновления —
  зависимости при обновлении уже стоят, `apt-get update` без интернета
  через прокси может висеть минутами; если пакетов на деле нет —
  ставятся несмотря на флаг.
- `tests/test_step9_updater.py` — 22 теста: парсинг версии, сравнение
  sha, атомарность статуса, все ветки API (403/409/502/503) через
  `app.test_client()` с подменённым `updater`, проверка что
  `start_update` не запускает реальных процессов в тестах.

### Безопасность

- **У сервиса нет аутентификации** — кнопка обновления доступна всем в
  локальной сети, если `http.host: 0.0.0.0`. Обязательные меры:
  `update.allow_from_ui: false` в конфиге скрывает кнопку и возвращает
  403 на `POST /api/update/start`; в README — явное предупреждение и
  рекомендация `http.host: 127.0.0.1` + SSH-туннель для недоверенных
  сетей. Своя система паролей/токенов сознательно не реализована — это
  отдельная задача, и наспех сделанная она хуже честного ограничения.

## [0.8.0] — 2026-09-08

### Исправлено

- **A1 (критично): назначенная зона не доезжала до дашборда.** Группа
  счётчика жила в двух местах — в SQLite и в in-memory `MeterRegistry`,
  а второе заполнялось только один раз при старте демона. После
  назначения зоны в «Настройках» дашборд показывал «— Без зоны —» до
  перезапуска сервиса. Исправлено на двух уровнях: push-синхронизация
  (`_sync_registry_groups()` в `api.py`) в конце каждого обработчика,
  меняющего привязку к зоне, и периодическая пересинхронизация
  (`BackgroundTasks._sync_groups()`).
- **A2:** `PATCH {"group": ""}` теперь действительно снимает зону —
  раньше пустая строка и `None` схлопывались в API, счётчик оставался в
  старой зоне.
- **A3:** переименование зоны больше не меняет её `id` и не теряет
  `created_at` — добавлен честный `GroupRepo.rename()`.
- **A4:** уникальность имени зоны больше не полагается на
  `COLLATE NOCASE` (в SQLite сворачивает регистр только ASCII) — новая
  колонка `name_norm`, казефолд-нормализация на стороне Python
  (корректно работает и с кириллицей).
- **A5:** переименование в занятое имя зоны возвращает 409 вместо
  тихого слияния; явное слияние — только через `{"merge": true}`.
- **A6:** вёрстка строки редактирования в реестре счётчиков — поля
  теперь строго под своими заголовками (`Имя | Группа | Комментарий |
  Роль | device_id | Serial | Действия`); каждая ячейка — один `<td>` с
  `<template x-if>` для просмотра/редактирования, порядок колонок
  физически не может разъехаться.
- **A7:** `colspan` пустой строки реестра исправлен на фактическое
  число колонок.
- **A8:** назначение зоны — через `<select>` (без свободного текста):
  «— Без зоны —», список зон, «+ Новая зона…»; убраны дублирующиеся
  `<datalist>` внутри `x-for`.
- **B2:** `initReports()` — `await loadSettings()` перед первой
  загрузкой ведомости (раньше «Комментарий» был пуст на первом рендере).
- **B3:** CSV-выгрузки (ведомость, профиль, сравнение, доступность,
  баланс, история параметра) экранируют `;`, кавычки и переводы строк.
- **B5:** подсветка пикового часа в профиле нагрузки — по ссылке на
  объект, а не по значению (раньше при равных максимумах подсвечивались
  все совпавшие бары).
- `AGENTS.md`: обновлён раздел «Что в работе» (баг с `<template>` уже
  исправлен), добавлены новые грабли.

### Добавлено

- **Массовое назначение зоны** в «Настройках»: чекбоксы в реестре
  счётчиков + панель «Выбрано N · [зона] · Применить».
- **Цвет зоны**: колонка `color` в `meter_groups`, палитра по кругу при
  создании, смена цвета в списке зон.
- **Русификация и категоризация параметров счётчика** (`channels.py`) —
  единый словарь: русское название, единицы измерения, подсказка,
  категория. «Основные» — плоской сеткой наверху, остальное — по
  сворачиваемым категориям (Напряжение / Ток / Мощность / Энергия /
  Качество сети / Служебные / Прочее). Незнакомый канал не теряется —
  отображается под своим именем в «Прочее». Состояние раскрытых
  категорий запоминается в `localStorage`.
- **График истории параметра**: клик по числовому параметру в карточке
  счётчика открывает линейный SVG-график (тот же стиль, что и
  `renderProfileSvg()`) с выбором периода (Час / Сутки / Неделя /
  Месяц / произвольный диапазон), сводкой мин/макс/среднее/последнее и
  выгрузкой CSV.
- Новые эндпоинты: `GET /api/meters/<id>/channel-history`,
  `GET /api/channels/dictionary`.
- Новые тесты: `tests/test_step8_groups.py` (регрессия A1-A5 и
  периодическая ресинхронизация), `tests/test_step8_channels.py`
  (консистентность словаря каналов).
- CI: `test_step5_flask_api.py`, `test_step6_webui.py`,
  `test_step8_groups.py`, `test_step8_channels.py` теперь запускаются
  в GitHub Actions (раньше — только step3/step4).
- Проверка баланса HTML-тегов `index.html` встроена в
  `test_step6_webui.py` (скриптом, не глазами).

### Изменено

- `_meter_detail()` (`api.py`) — в ответ добавлены поля `units`,
  `label`, `hint`, `category`, `main` для каждого канала (формат ответа
  не ломается, только новые поля).
- `MeterRepo`/`GroupRepo`: `GroupRepo.get_by_name()` ищет по
  `name_norm`; `GroupRepo.create()` может конфликтовать с
  `GroupNameConflict` вместо тихого создания дубля.
- Миграция `003_group_name_normalized.sql`: колонки `name_norm`,
  `color` в `meter_groups`, уникальный индекс по `name_norm`,
  дедупликация существующих дублей суффиксом при апгрейде.

### Известные ограничения

- `WbDbClient._call` по-прежнему поднимает новое MQTT-соединение на
  каждый RPC-вызов (D3). Для графика истории параметра это может быть
  заметно при частых кликах — на фронте добавлен троттлинг (не чаще
  одного запроса раз в ~300 мс). Полноценный переиспользуемый RPC-клиент
  с `loop_start()` и общей подпиской на wildcard-топик ответов — в
  планах, отложен как рискованный рефакторинг вне рамок этого релиза.

## [0.7.0] — 2026-05-28

### Добавлено

- **Настройки в веб-интерфейсе** (вкладка «Настройки») — управление
  счётчиками и зонами без CLI и SSH:
  - Сканирование MQTT: находит новые устройства и предлагает добавить.
  - Добавление, переименование, удаление счётчиков.
  - Inline-редактирование имени, зоны, комментария, роли прямо в таблице.
  - Управление зонами: создать, переименовать, удалить.
  - Autocomplete по существующим зонам при вводе.

- **Зоны** — группировка счётчиков по щитам/помещениям:
  - На дашборде карточки сгруппированы по зонам с цветными маркерами
    и сводкой мощности по зоне.
  - Цвет зоны детерминирован из её названия (всегда одинаковый).

- **Роли** — разделение вводных и потребительских счётчиков:
  - Три роли: `input` (Ввод), `consumer` (Потребитель), `other` (Прочее).
  - Бейдж **ВВОД** на карточке дашборда для вводных счётчиков.
  - Используются в отчёте «Баланс».

- **Комментарии** (`notes`) к счётчикам — отображаются на карточке
  (курсивом под зоной) и в таблице настроек.

- **История статусов** (`alert_repo.py`) — автоматическая запись переходов:
  - При смене статуса на `no_connection`/`device_error` — открывается
    запись с `started_at`.
  - При восстановлении — запись закрывается с `ended_at`.
  - Из пар started_at/ended_at вычисляются точные интервалы недоступности.

- **Пять отчётов** (вкладка «Отчёты»):
  1. **Ведомость расхода** — таблица по всем счётчикам за период,
     сгруппированная по зонам, итог по каждой зоне и общий итог.
  2. **Профиль нагрузки** — почасовой SVG-график выбранного счётчика,
     метрики (итого, пик, среднее, часов с данными), таблица по часам.
  3. **Сравнение периодов** — два периода рядом, Δ кВт·ч и Δ % с
     цветовой индикацией роста/снижения.
  4. **Доступность** — % времени на связи, суммарное время недоступности,
     число инцидентов; клик раскрывает список с датами от/до каждого.
  5. **Баланс** — ввод минус потребители = небаланс в кВт·ч и %. Три
     сводных карточки + детализация по каждой группе. Если вводных
     счётчиков нет — подсказка как их назначить.
  - Все отчёты выгружаются в **CSV** (UTF-8 BOM, открывается в Excel).

- **Аптайм счётчика** на карточке дашборда — если канал Uptime (s)
  включён в Device Manager WB.

- **Цветное время последнего обновления** на карточке: 🟢 < 2 мин,
  🟡 < 10 мин, 🔴 > 10 мин.

### Изменено

- Дашборд: карточки сгруппированы по зонам вместо плоского списка.
- `status.py`: два раздельных таймаута — `no_connection` (нет любых
  сообщений) и `no_measurement` (связь есть, но U/I = 0). Статус
  `no_measurement` теперь корректно отображается как «Нет нагрузки».
- `model.py`: добавлен `last_measurement_ts`, `MEASUREMENT_CHANNELS`,
  канал `Uptime` в `MAIN_CHANNELS`.
- `mqtt_client.py`: обновляет `last_measurement_ts` только для
  измерительных каналов (U/I/P/F) выше порога.
- `config.py`: дефолт `no_connection_timeout_s` поднят 300 → 600 с.
- `main.py`: `groups_repo` и `alert_repo` передаются в `ApiServer`
  и `StatusEngine`.
