# Инструкции для агентов

`wb-energy-meter` получает данные счётчиков Wiren Board через MQTT, хранит
реестр и агрегаты в SQLite и предоставляет Flask API и интерфейс Alpine/Leaflet.

## Общие правила

- Для текущего поведения сверяйтесь с кодом и покрывающими его тестами.
  `docs/status.md` фиксирует известные ограничения и пробелы проверки.
- Держите каждое правило в одном источнике: этот файл маршрутизирует к
  инструкциям, но не дублирует их.
- Применяйте ТЗ, только если задача указывает на него как на активное.
  Отменённое ТЗ не задаёт текущих требований.

## Инструкции по ветке задачи

- Для изменений Python или MQTT прочитайте [стиль Python](CODING_STANDARDS.md#стиль-python),
  [архитектуру и владение данными](CODING_STANDARDS.md#архитектура-и-владение-данными)
  и [совместимость с контроллером](CODING_STANDARDS.md#совместимость-с-контроллером).
- Для SQLite, миграций или HTTP API прочитайте [правила БД](CODING_STANDARDS.md#база-данных)
  и [проверки поведения API](CODING_STANDARDS.md#api-и-проверки-поведения).
- Для установщика, самообновления или конфигурации `wb-mqtt-serial` прочитайте
  [правила установки и обновления](CODING_STANDARDS.md#установщик-и-самообновление).
- Для тестов читайте [стандарты тестирования](CODING_STANDARDS.md#тестирование).
- Для runtime-зависимостей читайте
  [совместимость с контроллером](CODING_STANDARDS.md#совместимость-с-контроллером).
- Для содержимого пакета и вложенной статики читайте
  [правило упаковки](docs/agent-guides/frontend.md#инварианты-фронтенда).
- Для выпуска читайте
  [правила версий и релизов](CODING_STANDARDS.md#версии-и-выпуски).
- Для HTML, клиентского JavaScript, статики или браузерных UI-сценариев
  прочитайте [инструкции фронтенда](docs/agent-guides/frontend.md).
- Для запуска `tests/browser/run.py` в Linux без системных библиотек Chromium
  используйте [Linux-рецепт Playwright](docs/agent-guides/browser-testing-linux.md).
- При работе из Linux на Windows-mounted checkout открывайте
  [инструкцию Git](docs/agent-guides/git-windows-mount.md) только при
  ошибке unlink/lock.
- Если задача зависит от готовности функции, ручной проверки или активной работы,
  сверяйтесь с [текущим статусом](docs/status.md).
- Если задача прямо ссылается на активное ТЗ, откройте соответствующий
  `docs/TZ-*.md`; отменённые ТЗ помечены в своих шапках.
