# Однолинейная схема: проектная заметка (партия 14, 0.24.0)

Решение R3 (`docs/TZ-finish-plan.md` §7, §10): полноценный редактор схемы
на базе «Плана v3». Новых миграций и сущностей нет (R7, §2.9).

## 1. Инвентаризация (что уже есть)

| Что | Как устроено сейчас |
|---|---|
| Положение узла | строка `plan_items` (`kind='node'`, `node_id`, `geometry {x,y}`, `coord_space`). На плане этажа `image_px_xy_v2`, на холсте без картинки `canvas_xy_v2`; Y сверху вниз, в Leaflet `[H−y, x]`. |
| Линия на плане | строка `plan_edge_views` (`edge_id`, `from_item_id`, `to_item_id`, `waypoints`, `view_kind`). Сама связь — `electrical_edges`, одна на всю сеть. |
| Сохранение раскладки | `POST /api/v2/plans/<id>/layout`: одна транзакция, `expected_revision` = `canvas_revision`, при расхождении 409 `revision_conflict`; новые элементы в той же пачке — ссылками `$<индекс>`. Концы вида связи проверяются: значки на этом же плане, узлы совпадают с концами связи. |
| «План v2» | черновик + отмена; трассы с `waypoints` рисуются Geoman `Line` (`planV2StartDrawWaypoints`); 409 → флаг `planV2RevisionConflict` и модалка, черновик не теряется. |
| «План v3» | прямые действия без черновика; значки `circleMarker`, линии — прямые отрезки; живая карточка в общем 5-секундном `_pollTick`, ветка `planv3`. |
| Загрузка линии | раньше считалась на клиенте (`_planEdgeLiveMetrics`); в v2 API — только `rated_current_a`. |

## 2. Решения

**Схема = план `plan_kind='single_line'`.** Тот же узел живёт на плане этажа и
на схеме двумя (и более) строками `plan_items` с разным `plan_id`; числа
(`P`, баланс, загрузка) берутся из одних и тех же API по `node_id` / `edge_id`,
поэтому на всех планах они одинаковы, а итог объекта не меняется (A26: итог
считается по точкам учёта, не по значкам). На одной схеме узел может стоять
дважды (два значка).

**Где трасса.**
- *Автоматическая* ортогональная трасса **не хранится**: считается при каждой
  отрисовке чистой функцией `routeEdges` из положений значков. Поэтому
  перетаскивание узла «пересчитывает» её само, миграций и записи не нужно.
  Отходящие линии одного узла делят общий горизонтальный участок (шина на
  середине между рядами).
- *Ручная* трасса хранится в `plan_edge_views.waypoints` (`view_kind='structural'`)
  как **полная ломаная** (в координатах холста); при отрисовке первая и
  последняя точки заменяются живыми центрами значков, поэтому перетаскивание
  узла не рвёт трассу. Если после этого хоть один отрезок не горизонтален и не
  вертикален, трасса помечается «неортогональна». При рисовании («Нарисовать
  трассу», Geoman `Line`, завершение двойным щелчком) каждый щелчок считается
  углом: точки проходят `snapOrthogonal` и округляются до целых px.
  «Сделать автоматической» записывает `waypoints = null`.
- Новых полей нет: «ручная» = `waypoints` не пусто.

**Автораскладка** — чистая функция `layoutTree` без DOM
(`static/js/scheme-layout.js`, проверяется под `node`). Ряды: вводы (0), щиты и
ответвления по глубине, нагрузки — нижний ряд. По горизонтали каждому листу
своя ячейка, родитель по центру детей (поддеревья не пересекаются). Размер
ячейки — по ограничивающему прямоугольнику значка с подписью. Режимы: «разложить
неразмещённые» (по умолчанию; уже стоящие значки неподвижны, новые — по
свободным ячейкам) и «перераскладить всё» (после подтверждения). Результат
уходит одной операцией `/layout` с `canvas_revision`; для «отменить»
запоминаются прежние положения (и сохраняются тем же `/layout`). При 409 —
модалка конфликта; черновик (рассчитанная раскладка) не теряется.
Если дерево шире холста, функция возвращает `fits:false` и нужный размер: холст
фиксируется при создании плана (`canvas_width/height`), поэтому новая схема
создаётся сразу с размером «по топологии» (раскладка ×1,05, округление до 100,
не меньше 1200×700).

**Общий код (одна копия).** Пересчёт координат `[H−y, x]` ⇄ `(x, y)` выносится
в `core.js` (`_planXyToLatLng`, `_planLatLngToXy`); `plan-v2.js` и `plan-v3.js`
вызывают их, своих копий не держат. Рисование трассы использует тот же
Geoman `Line` + привязку к осям из `scheme-layout.js` (`snapOrthogonal`).
Процент загрузки линии — только `GET /api/v2/topology/edge-loads`
(`line_load.py`, A31/A32/A43); клиент его не считает.

**Экран.** Новый файл `static/js/single-line.js` (часть Alpine): значки
`L.divIcon` с SVG по типу узла, подписи (текст — через `_planEscapeHtml`, A45),
двухстрочные подписи линий (имя или «A → B», счётчик и P; ставятся у верха
последнего вертикального отрезка трассы, чтобы не перекрываться), значок баланса щита (`POST
/api/v2/topology/nodes/<id>/balance`), список «Неразмещённые», переключатель вида
планов, `@media print`. Обновление P/баланса — в ветке `planv3` существующего
`_pollTick`; новых таймеров нет. Для схем `plan-v3.js` вызывает отрисовку
`single-line.js`; поведение плана этажа не меняется.

## 3. Ограничения

- Размер холста не меняется после создания плана; нетипично широкое дерево
  требует новой схемы большего размера.
- Многопитание (резервный источник) рисуется, но раскладка берёт первого
  родителя (по `id`); АВР и переключение источников не реализуются (R-границы).
- Связи с несколькими родителями и циклы раскладка не ломают: лишние связи
  рисуются по тем же правилам, зацикливание отсекается списком посещённых.
