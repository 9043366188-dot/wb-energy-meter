## 1. Что нужно сделать

Новая вкладка «План»: пользователь загружает картинку плана объекта (цех,
этаж, однолинейная схема), обводит на ней контуры зон, и дальше видит
живую картину — какая зона сколько потребляет, где что не в порядке. Между
зонами рисуются кабельные связи, толщина и цвет которых отражают реальную
нагрузку.

Решения заказчика:

- **План — картинкой.** Не географическая карта, тайлы OSM не нужны.
- **Зона — контур-полигон**, обводится мышью.
- **Связь — линия с живой нагрузкой**, а не просто подпись.

Ключевое требование по объёму: это **не ГИС и не SCADA**. Нужно нанести
зоны на план, показать по клику аккуратную карточку с показателями и
соединить зоны линиями. Всё, что сверх — не делать.

## 2. Библиотека: Leaflet. Велосипед не изобретать

Взять **Leaflet 1.9.4** (BSD-2-Clause) в режиме `L.CRS.Simple`. Это
штатный механизм библиотеки для работы с обычным изображением как с
картой: одна единица координат = один пиксель картинки, никакой географии.
Официальный пример — [Non-geographical maps](https://leafletjs.com/examples/crs-simple/crs-simple.html).

Что берём готовым и **не пишем руками**: панорамирование и зум с инерцией,
попапы и тултипы, полигоны и полилинии, hit-testing по клику, слои и их
переключение, обработка событий.

Для рисования контуров зон мышью — **Leaflet-Geoman Free 2.20.0** (MIT).

Почему не другое:

- **MapLibre GL / OpenLayers** — вектор, WebGL, на порядок больше кода и
  сложности. Для «зоны на картинке» это стрельба из пушки.
- **Своя реализация на голом SVG** — соблазнительно (в проекте уже есть
  рукописные SVG-графики), но панорамирование, зум, попадание курсором в
  полигон и корректная работа на тач-экране — это ровно та рутина, ради
  которой библиотеку и берут.

Версия Leaflet 1.9.4 датирована 2023 годом — это не заброшенность, а
зрелость. Библиотека доделана.

## 3. Четыре грабли. Прочитать до начала

### 3.1. Вкладки на `<template x-if>` уничтожают DOM карты

Главное. Сейчас вкладки переключаются так:

```html
<template x-if="tab=='dash'"> ... </template>
```

`x-if` **удаляет узлы из DOM** при переключении. Leaflet держит собственный
DOM внутри контейнера и ссылку на этот контейнер. Если контейнер вырезали
из-под карты, при возврате на вкладку получится либо пустой серый
прямоугольник, либо исключение из недр Leaflet, либо утечка: старый
экземпляр карты остаётся висеть с подписанными обработчиками.

Два допустимых решения, выбрать одно:

1. **Пересоздавать карту при входе на вкладку.** В `x-init` контейнера
   создавать `L.map(...)`, а перед уничтожением — обязательно
   `map.remove()`. Без `map.remove()` будет утечка обработчиков и
   «Map container is already initialized» при повторном входе.
2. **Перевести вкладку «План» на `x-show`** вместо `x-if`, чтобы DOM
   не удалялся. Тогда карта создаётся один раз.

Рекомендуется вариант 2 для вкладки «План» (остальные вкладки не трогать):
меньше шансов на утечку, и состояние карты — положение, зум — сохраняется
между переключениями, что пользователю удобно.

### 3.2. `invalidateSize()` после показа

Leaflet вычисляет размеры при инициализации. Если контейнер в этот момент
скрыт (`display:none` у неактивной вкладки), карта решит, что её размер
0×0, и отрисуется мусором. После того как вкладка стала видимой,
обязательно:

```js
this.$nextTick(() => map.invalidateSize());
```

Это же нужно после изменения размера окна.

### 3.3. Контейнеру нужна явная высота

`#map { height: ... }` в CSS обязателен. Без явной высоты блок схлопнется в
ноль, и карта не появится вообще — без единой ошибки в консоли. Симптом
ровно такой же, как у истории с незакрытым `<template>`, и диагностируется
так же плохо. Задать `height: calc(100vh - 220px); min-height: 420px`.

### 3.4. Alpine не должен трогать внутренности карты

Не вешать `x-for` / `x-text` / `:class` на элементы **внутри** контейнера
карты. Alpine и Leaflet будут драться за одни и те же узлы. Слои, попапы и
стили менять только императивно, через API Leaflet
(`layer.setStyle()`, `layer.bindPopup()`), из обычных методов Alpine-компонента.
Сам объект карты держать вне реактивности Alpine — например, в замыкании
модуля или в поле, помеченном как не-реактивное; `L.Map` в реактивном
объекте Alpine оборачивается в Proxy и ведёт себя непредсказуемо.

## 4. Вендоринг: библиотеки кладём локально, а не с CDN

Сейчас `index.html` тянет Alpine с `cdn.jsdelivr.net`. Это значит, что
**на объекте без интернета в браузере интерфейс не открывается вообще**.
Для промышленного контроллера в изолированной сети это неприемлемо, а
карта добавила бы вторую такую зависимость.

Положить в `wb_energy_meter/static/vendor/`:

| Файл | Источник (версия пинится) | Размер |
|---|---|---|
| `leaflet.js` | `leaflet@1.9.4/dist/leaflet.js` | 147 КБ |
| `leaflet.css` | `leaflet@1.9.4/dist/leaflet.css` | 15 КБ |
| `images/*` | `leaflet@1.9.4/dist/images/` | ~10 КБ |
| `leaflet-geoman.min.js` | `@geoman-io/leaflet-geoman-free@2.20.0` | 287 КБ |
| `leaflet-geoman.css` | то же | 26 КБ |
| `alpine.min.js` | `alpinejs@3.13.0/dist/cdn.min.js` | 42 КБ |

Итого ~530 КБ. Требования:

- Скачать с официального CDN по **точным** версиям, зафиксировать
  SHA-256 каждого файла в `static/vendor/VENDOR.md` вместе с URL
  источника и версией.
- Рядом положить файлы лицензий: `LICENSE-leaflet` (BSD-2-Clause),
  `LICENSE-geoman` (MIT), `LICENSE-alpine` (MIT).
- `leaflet.css` ссылается на `images/marker-icon.png` и другие —
  каталог `images/` вендорить обязательно, иначе будут битые иконки.
- В `index.html` заменить CDN-ссылку Alpine на локальную.

### Flask должен научиться отдавать статику

Сейчас есть только `@app.route("/")`, отдающий `index.html`. Добавить
маршрут для `static/vendor/`:

- Путь запроса — **только** из белого списка имён файлов или через
  `werkzeug.utils.safe_join`; никакой конкатенации с тем, что пришло от
  клиента. Обход каталога (`../`) должен быть невозможен.
- Правильные MIME-типы, `Cache-Control: public, max-age=86400`,
  заголовок `X-Content-Type-Options: nosniff`.

## 5. Схема БД — миграция `004_site_plan.sql`

Следующий свободный номер — 004. Не забыть в конце файла
`INSERT INTO schema_migrations (version, name, applied_at) VALUES
(4, 'site_plan', strftime('%s','now'));` — как в 001–003.

```sql
CREATE TABLE site_plans (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    name          TEXT    NOT NULL,
    image_file    TEXT    NOT NULL,   -- имя файла, генерируем МЫ
    image_width   INTEGER NOT NULL,
    image_height  INTEGER NOT NULL,
    is_default    INTEGER NOT NULL DEFAULT 0,
    created_at    INTEGER NOT NULL,
    updated_at    INTEGER NOT NULL
);

CREATE TABLE plan_zones (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    plan_id     INTEGER NOT NULL REFERENCES site_plans(id) ON DELETE CASCADE,
    group_id    INTEGER NOT NULL REFERENCES meter_groups(id) ON DELETE CASCADE,
    shape_type  TEXT    NOT NULL DEFAULT 'polygon',  -- polygon | marker
    geometry    TEXT    NOT NULL,   -- JSON: [[y,x],...] либо [y,x]
    anchor      TEXT,               -- JSON [y,x]: точка привязки связей и подписи
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_plan_zones_plan_group ON plan_zones(plan_id, group_id);

CREATE TABLE plan_links (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    plan_id         INTEGER NOT NULL REFERENCES site_plans(id) ON DELETE CASCADE,
    from_zone_id    INTEGER NOT NULL REFERENCES plan_zones(id) ON DELETE CASCADE,
    to_zone_id      INTEGER NOT NULL REFERENCES plan_zones(id) ON DELETE CASCADE,
    source_meter_id INTEGER REFERENCES meters(id) ON DELETE SET NULL,
    rated_current_a REAL,           -- допустимый ток кабеля, необязательно
    waypoints       TEXT,           -- JSON [[y,x],...] — изломы трассы
    label           TEXT,           -- «АВВГ 4х95, 120 м»
    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL
);
CREATE INDEX idx_plan_links_plan ON plan_links(plan_id);
```

Зона привязывается к **существующей** `meter_groups` — не заводить
параллельную сущность. Зоны уже есть в «Настройках», план лишь наносит их
на картинку. Цвет зоны берётся из `meter_groups.color` (добавлен в
v0.8.0), а не задаётся заново.

Координаты хранятся **в пикселях исходного изображения**, ось Y — вниз от
левого верхнего угла. В `CRS.Simple` у Leaflet координаты имеют вид
`[y, x]` (по аналогии с `[lat, lng]`) — на этом легко ошибиться, завести
две функции-конвертера и покрыть их тестом.

## 6. Загрузка плана

`POST /api/plans` — `multipart/form-data`, поля `name` и `file`.

Требования к безопасности (файл приходит извне, его потом отдаёт наш же
сервер):

- **Только PNG и JPEG.** Проверять по сигнатуре файла
  (`\x89PNG\r\n\x1a\n`, `\xff\xd8\xff`), а не по расширению и не по
  заголовку `Content-Type` из запроса.
  **SVG не принимать** — его безопасная отдача требует санитизации и
  строгих заголовков, это отдельная задача. В сообщении об ошибке прямо
  посоветовать экспортировать план в PNG.
- Максимальный размер — 10 МБ, проверять до чтения в память
  (`request.content_length` плюс жёсткий предел при чтении).
- **Имя файла на диске генерируем мы**: `plan_<id>.png` / `.jpg`.
  Имя из запроса не использовать нигде, даже в логе — только как
  отображаемое значение после экранирования.
- Каталог: `<каталог БД>/plans/` (то есть на `/mnt/data`, переживает
  обновление сервиса). Создавать при необходимости.
- Отдача: `GET /api/plans/<id>/image` — читает файл по `id` из БД,
  никаких путей из запроса. Заголовки `X-Content-Type-Options: nosniff`,
  `Cache-Control: private, max-age=3600`.

**Размеры картинки — без Pillow.** Новых зависимостей не добавлять
(правило проекта). Ширину и высоту достать из заголовков стандартной
библиотекой:

- PNG: байты 16–24 после сигнатуры — `struct.unpack(">II", data[16:24])`.
- JPEG: пройти по маркерам, взять размеры из `SOF0`–`SOF3`, `SOF5`–`SOF7`,
  `SOF9`–`SOF11`, `SOF13`–`SOF15`.

Не распознали размеры — отказ с внятным текстом, файл не сохранять.

## 7. API

Все ответы — в существующем стиле `api.py` (`json_response`, русские
тексты ошибок).

**Планы**

- `GET /api/plans` — список планов.
- `POST /api/plans` — загрузка (см. §6), `201`.
- `GET /api/plans/<id>` — план с зонами и связями (всё для отрисовки).
- `GET /api/plans/<id>/image` — картинка.
- `PATCH /api/plans/<id>` — переименовать, назначить планом по умолчанию.
- `DELETE /api/plans/<id>` — удалить план, зоны, связи и файл картинки.
  Подтверждение — на стороне UI.

**Зоны**

- `PUT /api/plans/<id>/zones/<group_id>` — создать или обновить контур.
  Тело: `{shape_type, geometry, anchor}`.
  Валидация: `geometry` — массив от 3 точек для полигона; все координаты
  внутри `[0, image_width] × [0, image_height]`; числа конечные.
  Мусор — `400`, ничего не писать.
- `DELETE /api/plans/<id>/zones/<group_id>` — убрать зону с плана
  (сама зона в реестре остаётся).

**Связи**

- `POST /api/plans/<id>/links` — создать.
- `PATCH /api/plans/<id>/links/<link_id>` — изменить.
- `DELETE /api/plans/<id>/links/<link_id>` — удалить.
  Валидация: обе зоны существуют и принадлежат этому плану;
  `from_zone_id != to_zone_id`; `rated_current_a` — положительное число
  либо `null`.

**Живые данные**

- `GET /api/plans/<id>/live?period=today` — то, что обновляется по таймеру:

```json
{
  "zones": [{
    "group_id": 3, "name": "Цех 1", "color": "#4a9",
    "meters_total": 4, "meters_ok": 3,
    "worst_status": "no_connection",
    "power_kw": 12.408,
    "consumption_kwh": 184.2
  }],
  "links": [{
    "id": 7, "current_a": 84.1, "power_kw": 55.2,
    "load_pct": 70.1, "state": "warn"
  }]
}
```

Считать из уже готовых источников: мощность зоны — сумма `Total P` по
счётчикам группы (как в существующем `zonePower()`), расход — через
`consumption_service` за период, статусы — из реестра. Ничего нового не
изобретать.

Ток связи: у счётчика `source_meter_id` взять максимум из
`Irms L1/L2/L3`; `power_kw` — его `Total P`. Если счётчик не задан или
данных нет — `null`, и линия рисуется нейтрально.

## 8. Интерфейс

Новая вкладка **«План»** между «Дашборд» и «Расход».

### 8.1. Режим просмотра (основной)

- План на всю ширину, зоны — полупрозрачные полигоны цвета зоны
  (заливка ~25 %, контур плотный). Наведение — подсветка.
- **Клик по зоне → аккуратная карточка** (попап Leaflet, но оформленный
  под стиль проекта, а не дефолтный): название зоны, счётчиков всего и
  сколько в порядке, текущая мощность в кВт, расход за выбранный период,
  и — если что-то не так — строка с худшим статусом. Внизу ссылка
  «Открыть счётчики зоны», ведущая на дашборд с фильтром по зоне.
  Карточка — главная ценность вкладки, ей стоит уделить внимание:
  крупная цифра мощности, под ней остальное помельче.
- Зона со счётчиком не в порядке — пульсирующий контур или заметная
  рамка тревожного цвета. Не мигать быстро: раздражает на дежурном
  мониторе, достаточно плавной анимации в 2 секунды.
- **Связи** — линии между `anchor` зон через `waypoints`.
  Толщина: 2–10 px по мощности (или току) относительно максимума на
  плане. Цвет: если задан `rated_current_a` — зелёный до 70 %, жёлтый
  70–90 %, красный выше; если не задан — нейтральный `var(--accent2)`.
  Наведение — тултип с `label`, током и процентом загрузки.
- Селектор периода вверху — переиспользовать существующий `presets`.
- Обновление живых данных раз в 5 секунд, как на дашборде. Обновлять
  **только стили и содержимое попапов**, не пересоздавая слои: иначе
  открытый попап будет закрываться каждые 5 секунд.
- Если планов нет — аккуратная заглушка с кнопкой «Загрузить план».

### 8.2. Режим редактирования

Переключатель «Редактировать» в углу.

- Загрузка плана: выбор файла, имя, прогресс.
- **Рисование зоны**: выбрать зону из списка существующих групп → нажать
  «Обвести» → Geoman включает режим полигона → двойной клик завершает.
  Готовый контур можно двигать и править вершинами. Кнопка «Сохранить».
- Зоны, уже нанесённые на план, помечены в списке галочкой.
- **Рисование связи**: «Добавить связь» → клик по зоне-источнику → клик
  по зоне-приёмнику → линия создана. Промежуточные изломы — режим
  полилинии Geoman. В боковой форме: подпись, счётчик-источник
  (выпадающий список счётчиков), допустимый ток.
- Удаление зоны с плана и удаление связи — с подтверждением в
  существующем стиле `confirm-overlay`.
- Все изменения сохраняются явной кнопкой, не автоматически по каждому
  движению мыши.

## 9. Тесты

Новый `tests/test_step11_plan.py` — самостоятельный скрипт (не pytest),
без сети и без реальных картинок из интернета.

   (сгенерировать минимальные валидные заголовки прямо в тесте),
   битый файл → внятная ошибка.
2. Отказ на файле с чужой сигнатурой (например, GIF или SVG),
   переименованном в `.png`; файл **не сохраняется** на диск.

7. Связь: `from == to` → 400; зона из чужого плана → 400;
   отрицательный `rated_current_a` → 400.

   существующий API уносит её зону с плана (проверить, что реестр

## 12. Чего делать нельзя

- **Не добавлять зависимостей Python** — только стандартная библиотека.
  В частности, никакого Pillow ради размеров картинки.
- **Не тянуть ничего с CDN во время работы** — все библиотеки локально.
- Не подставлять в пути, URL и shell-команды ничего, что пришло из
  HTTP-запроса, включая имя загружаемого файла.
- Не принимать SVG в этой версии.
- Не заводить вторую сущность «зона» — использовать существующие
  `meter_groups`.
- Не строить редактор схем, слои, кластеризацию, печать, экспорт в DXF и
  прочее. Зоны, карточка по клику, связи — и всё.
- Не переводить остальные вкладки с `x-if` на `x-show` заодно: это
  затронет весь интерфейс, а задача не про это.
- Не ломать поддержку Python 3.9 (CI гоняет 3.9–3.12).
- Не менять формат существующих ответов API — только добавлять.
