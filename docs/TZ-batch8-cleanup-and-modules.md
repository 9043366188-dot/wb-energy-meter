## 2. Поправки к заданию партии 7

**2.1. Коммит `a1ecf33` уже сделан, его нельзя потерять.** В нём две
правки, которые пересекаются с этапом 4:

- `PATCH /api/v2/topology/nodes/<id>` теперь принимает `kind`, проверяет
  инварианты леса и отвечает **400** на тело без единого знакомого поля
  (раньше был молчаливый 200, из-за которого смена типа «работала», не
  меняя ничего). В карточке узла «Плана v3» появилось поле «Тип»;
- `points_without_location` в `/api/v2/validation` засчитывает «где
  стоит», заданное у **узла** линии, которую точка измеряет.

Удаляя простой режим, **не трогать** `located_point_ids` в
`v2_validation` и поле «Тип» в карточке узла. Тесты, которые их держат:
`test_step39_plan_v3.py::test_node_kind_change_and_forest_invariants_still_enforced`,
`test_step30_validation_summary.py::test_points_without_location_counts_node_of_measured_edge`.

**2.2. Пункт задания партии 7 про `no_plan` — уже верен, менять нечего.**
Проверено отдельно: как только узел размещён на плане, точки его линий
перестают считаться неразмещёнными. Убрать нужно **только** ветку
«собственный узел точки простого режима» (`sm-pt-*`), как и написано в
C2, — сам механизм «по узлам измеряемой линии» правильный.

**2.3. Гейт «браузерный набор зелёный» теперь исполним локально.** В
задании партии 7 он выглядел как обещание на CI. Это больше не так:
`tests/browser/run.py` запускается в песочнице (рецепт в `AGENTS.md`).
Значит, любой пункт этой партии, затрагивающий интерфейс, проверяется
браузером **до** коммита, а не «в браузере не открывалось».

## 5. Ограничения проекта

Те же, что всегда, повторяются потому, что каждое нарушение уже стоило
рабочего контроллера:

- только стандартная библиотека Python плюс flask, paho-mqtt, pyyaml;
  playwright — тестовая зависимость, в рантайм не входит;
- на контроллере Python 3.9, Flask 1.1.2, Werkzeug 1.0.1; job
  `legacy-deps` в CI — ровно для этого, прогонять оба набора;
- никаких CDN; у `<template x-if>` ровно один корневой элемент;
- имя шага в `ci.yml` с `": "` внутри — **в кавычках**, иначе YAML
  невалиден и GitHub Actions молча не запускает workflow целиком;
- `DEFAULT_UI_SET` остаётся `'classic'`;
- формат существующих ответов API не менять, только добавлять;
- любая предметная запись — через протокол ревизий, при 409 понятный
  текст;
- **200 на запрос, который ничего не изменил, — ошибка** (новое правило
  в `AGENTS.md`): тест на изменение обязан перечитать сущность и сверить
  значение, а не только код ответа;
- к каждой проверке «отказ» — парная «легитимный запрос работает»;
- `git push` не делать, пользователь пушит сам.
