# ТЗ v0.11.1 — самопроверка интерфейса и защита от белого экрана

**Проект:** `wb-energy-meter` (Wiren Board 8.x + WB-MAP3E)
**Базовая версия:** 0.11.0
**Целевая версия:** 0.11.1
**Рабочий каталог:** `C:\wb-energy-meter-repo\wb-energy-meter`
**Дата составления:** 09.09.2026

---

## 1. Что случилось и почему это ТЗ существует

09.09.2026 обновление до v0.11.0 положило боевой контроллер. Маршрут
`/static/vendor/<file>` делал `from werkzeug.utils import safe_join`, а на
Debian bullseye (`python3-werkzeug` 1.0.1) эта функция лежит в
`werkzeug.security`. Импорт падал, маршрут отдавал 500, `alpine.min.js` не
загружался, Alpine не стартовал — и интерфейс превращался в белый экран с
намертво залипшей вкладкой. Сам баг уже исправлен.

Не исправлены две вещи, из-за которых **безобидная опечатка обернулась
выездом на объект**:

1. **Автооткат не сработал.** `self-update.sh` после установки проверяет
   `systemctl is-active` и `GET /health`. Оба ответили «всё хорошо»:
   демон жив, `/health` отдаёт `{"ok": true}` независимо от того, работает
   интерфейс или нет. Механизм отката, написанный ровно для такого
   случая, не увидел поломки.
2. **Интерфейс молчит, когда ломается.** Пользователь видит белую
   страницу. Ни сообщения, ни подсказки, ни строчки в логе сервиса —
   потому что ошибка целиком на стороне браузера.

Задача: закрыть обе. Это небольшая работа, но она превращает класс
«обновился и всё умерло молча» в «обновление откатилось само» либо, в
худшем случае, в «на экране написано, что именно сломалось».

## 2. Задача 1 — эндпоинт самопроверки

### 2.1. Новый `GET /api/selfcheck`

Сервис сам проверяет, что интерфейс в принципе может загрузиться:

1. Прочитать `static/index.html`.
2. Достать из него все ссылки вида `src="/static/..."` и
   `href="/static/..."` (регулярка по атрибутам, как в
   `test_static_vendor_serves_every_referenced_file`).
3. Для каждой — убедиться, что файл существует на диске, читается и
   непустой. **Не ходить по HTTP сам к себе** — это лишний виток и риск
   поймать таймаут; проверять файлы напрямую, той же логикой разрешения
   пути, что и маршрут статики, чтобы проверка совпадала с реальностью.
4. Ответ:

```json
{
  "ok": false,
  "checked": 6,
  "failed": [
    {"ref": "/static/vendor/alpine.min.js", "reason": "файл не найден"}
  ],
  "version": "0.11.1"
}
```

`ok: true` и пустой `failed` — когда всё на месте. HTTP-код **всегда 200**:
это диагностический эндпоинт, а не сама ошибка; читать надо поле `ok`.
Если `index.html` не прочитался — `ok: false` с внятной причиной, но всё
равно 200 и без исключений.

### 2.2. `self-update.sh` проверяет и его

В `verify_after_install()` рядом с существующими проверками
`systemctl is-active` и `/health` добавить третью: `GET /api/selfcheck`
должен вернуть 200 **и** `"ok": true`. Разбирать ответ без `jq` (его может
не быть на контроллере) — например `python3 -c` с `json.load` из stdin.

Не прошла — ведём себя ровно так же, как при неподнявшемся сервисе:
статус `rolling_back`, откат `/opt/wb-energy-meter` из
`.rollback`, перезапуск, статус `rolled_back`. Никакой новой ветки
логики: переиспользовать существующий `attempt_rollback`.

В сообщение статуса и в `update.log` писать, **что именно** не прошло —
список `failed` из ответа. Иначе пользователь опять останется с
«обновление откатилось» и без причины.

### 2.3. Старый сервис не знает про `/api/selfcheck`

Важная тонкость. При обновлении **со старой версии** новый
`self-update.sh` из архива запускается, а проверять он будет уже новый
сервис — там эндпоинт есть. Но возможен и обратный порядок при откате:
откатились на v0.11.0, где `/api/selfcheck` нет, и он отдаст 404.
**404 на этом эндпоинте не считать провалом** — трактовать как «проверка
недоступна», логировать и опираться на `/health`, как раньше. Иначе откат
на исправную старую версию будет выглядеть как неудача.

## 3. Задача 2 — заглушка вместо белого экрана

В `index.html` добавить блок, который виден **по умолчанию** и исчезает,
когда интерфейс успешно стартовал.

Требования:

- **Только голый HTML/CSS/JS.** Ни Alpine, ни Leaflet: заглушка обязана
  работать именно тогда, когда они не загрузились. Никаких `x-show`,
  `x-if`, `x-text` — они не сработают.
- Собственные стили инлайном или в существующем `<style>`, но **без CSS-
  переменных темы** — их проставляет Alpine через `:data-theme`, а его
  может не быть. Задать цвета явно.
- Скрывать блок из `init()` Alpine-компонента (он вызывается в `x-init`
  на `<html>`): например `document.getElementById('boot-error').remove()`.
  Раз `init()` выполнился — Alpine жив, заглушка не нужна.
- Дополнительно повесить на `window` обработчик `error` **в режиме
  перехвата** (`window.addEventListener('error', handler, true)`) — он
  ловит и ошибки загрузки `<script>`/`<link>`, у которых `event.target`
  указывает на не загрузившийся элемент. Собрать список того, что не
  загрузилось, и показать в заглушке.
- Текст по-русски, для инженера, с конкретикой:

  > **Интерфейс не запустился.**
  > Не загрузились файлы: `/static/vendor/alpine.min.js`
  > Проверьте на контроллере:
  > `curl -sI http://127.0.0.1:8080/static/vendor/alpine.min.js`
  > `journalctl -u wb-energy-meter -n 50`

  Пути показывать реальные, из собранного списка; если список пуст —
  общий текст без выдумывания конкретики.
- Заглушка не должна мешать нормальной работе: пока Alpine не стартовал,
  проходит доля секунды, и на быстрой машине блок мелькнёт. Чтобы не
  мигало — показывать его не сразу, а по таймеру через 1.5 секунды
  (`setTimeout`), и снимать таймер, когда `init()` отработал.

## 4. Чего делать нельзя

- Не добавлять зависимостей Python — только стандартная библиотека.
  В частности `jq` на контроллере может не быть, JSON разбирать питоном.
- Не менять формат существующих ответов API — только добавлять.
- Не ходить из `/api/selfcheck` по HTTP к самому себе.
- Не трогать логику отката — переиспользовать `attempt_rollback`.
- Не делать заглушку на Alpine: она обязана работать без него.
- Не ломать поддержку Python 3.9.

## 5. Проверка

**Обязательно прогнать тесты на ДВУХ наборах версий.** Именно
несовместимость со старыми библиотеками и стала причиной аварии.

```bash
# как в CI и в разработке
pip install "paho-mqtt>=1.6,<3" "pyyaml>=5.4" "flask>=1.1" --break-system-packages

# как на контроллере (Debian bullseye) — отдельный venv
python3 -m venv /tmp/venv_old
/tmp/venv_old/bin/pip install "flask==1.1.2" "werkzeug==1.0.1" \
    "jinja2<3" "itsdangerous<2" "markupsafe<2" "paho-mqtt>=1.6,<3" "pyyaml>=5.4"
```

Все тесты из `tests/` запускаются по одному (`python3 tests/<файл>.py`),
не через pytest. Три теста (`test_step3_daemon`, `test_step3_e2e`,
`test_step4_daemon`) требуют локального mosquitto и в песочнице падают —
это ожидаемо.

Новые тесты в `tests/test_step11_plan.py` (или отдельный
`test_step12_selfcheck.py` — на ваше усмотрение, но добавить в CI и в
`AGENTS.md`):

1. `/api/selfcheck` при целых файлах → `ok: true`, `failed` пуст.
2. Убрать/опустошить один вендоренный файл → `ok: false`, он в `failed`,
   код ответа всё равно 200.
3. `index.html` нечитаем → `ok: false`, 200, без исключения.
4. То же самое на **старом** Flask.
5. Заглушка есть в `index.html`, содержит подсказку с `journalctl`, и в
   ней нет ни одной директивы Alpine (`x-show`, `x-if`, `x-text`,
   `x-data`) — иначе она не сработает в том самом случае, ради которого
   написана.
6. `bash -n scripts/self-update.sh` проходит.

Плюс существующие обязательные проверки: `compileall`, баланс тегов
`index.html` **скриптом**, `node --check` по извлечённому JS.
